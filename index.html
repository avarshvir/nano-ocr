NanoOCR

An ultra-lightweight, 18MB Optical Character Recognition engine built from scratch for edge devices and embedded systems.

GitHub PyPI
pip install nano-ocr

Quick Start

from nano_ocr import NanoOCR

# Initialize the engine (automatically loads weights)
ocr = NanoOCR()

# Extract text and metrics from an image
result = ocr.predict("test_image.png")

print(f"Text: {result.text}")
print(f"Confidence: {result.confidence}")
print(f"Latency: {result.inference_time} ms")

How We Built It

1. The Architecture

NanoOCR is powered by a 4.8 million parameter CRNN (Convolutional Recurrent Neural Network). It uses a 7-layer VGG-style CNN with asymmetric max-pooling to extract feature maps from tall, narrow characters. The features are fed into a 256-hidden-size Bidirectional LSTM to understand spatial context, and decoded using CTC Loss (Connectionist Temporal Classification) to align text without needing perfect letter segmentation.

2. The Data Engineering

Training on millions of images crashes standard environments like Google Colab due to memory limits. To solve this, we engineered a custom streaming pipeline. Instead of downloading datasets entirely, the pipeline iterated and streamed files one-by-one directly into the GPU, maintaining a near-zero memory footprint during massive training runs.

3. The 3-Phase Training Strategy

  • 1
    Phase 1 (Proof of Concept): Trained on 320,000 synthetic images to establish character alignment, achieving 56.27% baseline accuracy on unseen data.
  • 2
    Phase 2 (Foundational Scaling): Scaled up to 2.32 Million images from the MJSynth dataset using the streaming pipeline, bumping accuracy to 71.57%.
  • 3
    Phase 3 (Frontier Fine-Tuning): Froze the core CNN layers and fine-tuned the head on 2,000 real-world IIIT5k images. This prevented "catastrophic forgetting" of the synthetic data while adapting the model to messy, real-world scene text.

Error Typology & Confidence

In a 15,000-character test, the model exhibited highly predictable failure modes: 602 substitutions (e.g., confusing 'O' with '0'), 628 deletions (missing thin characters), and only 77 insertions (hallucinations). Furthermore, the model is highly calibrated: it reports a 95.7% confidence score when it is correct, and automatically drops to 76.7% when incorrect, making it ideal for automated pipeline fail-safes.

Applications

  • IoT & Edge Devices: Low memory footprint (18MB) makes it perfect for Raspberry Pi.
  • Video Processing: High FPS allows for real-time subtitle extraction.
  • Automated Pipelines: High confidence calibration enables safe automation.
